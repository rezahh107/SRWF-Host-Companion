# SRWF Host Companion v0.2.0

Second personal/project-specific GitHub release of SRWF Host Companion.

This release adds one narrowly scoped capability: an independently selected **Inbox Page** can now receive the exact same existing SRWF Full Width host canvas already used by Registration.

## Highlights

- Adds an independent `صفحه اینباکس` selector and explicit Inbox apply action under `Settings → SRWF Host`.
- Reuses the existing canonical Full Width template/canvas; no second Inbox or Operational template is introduced.
- Evolves configuration to schema v2 with exactly `registration` and `inbox` page roles while preserving valid schema-v1 Registration state safely.
- Keeps Registration and Inbox mutations independent: changing one role preserves the other role's configuration and assignment.
- Preserves the previous selected page rather than silently reverting or rewriting its template.
- Keeps existing Registration diagnostics Registration-focused; Inbox-specific diagnostics and automatic repair are intentionally out of scope.
- Includes exact-target integration and real-browser qualification for the Inbox host-canvas path.

## Installation

Download `srwf-host-companion-0.2.0.zip`, then install it through WordPress under **Plugins → Add New → Upload Plugin**.

## What Inbox support means

Inbox support in `v0.2.0` is deliberately limited to the WordPress host page:

```text
select Inbox Page
→ persist the Inbox page ID
→ explicitly apply the existing SRWF Full Width host template
→ verify assignment/readback
```

This release does **not** change Gravity Flow Inbox behavior, workflow state, assignments, permissions, GPP presentation, or the internal styling/content of Inbox.
